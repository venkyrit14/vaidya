# Vaidya Data Schema

## Purpose

Vaidya is an AI-powered revenue recovery agent.

It processes three types of revenue-at-risk events:

1. Payment failures
2. Checkout abandonment
3. Overdue B2B invoices

All three event types are normalized into a common revenue-at-risk representation.

The system then:

Detect → Diagnose → Retrieve Evidence → Recommend Intervention → Policy Check → Execute/Escalate → Measure Recovery → Audit

---

# 1. Data Lineage

Vaidya uses three categories of data:

### Public / Razorpay-inspired

Fields whose structure is based on publicly documented Razorpay payment concepts.

Examples:

- payment status
- amount
- currency
- payment method
- order/customer identifiers
- payment error information

These do NOT represent private Razorpay production data.

### Public Dataset Derived

Fields derived from the Kaggle transaction dataset used as a behavioral/fraud foundation.

Source:

`data/raw/fraudTrain.csv`

Relevant source fields:

- trans_num
- trans_date_trans_time
- cc_num
- merchant
- category
- amt
- city_pop
- is_fraud

### Synthetic / Derived

Fields that are generated by Vaidya for the buildathon because public datasets do not provide the complete revenue recovery lifecycle.

Examples:

- checkout abandonment
- overdue invoices
- failure scenarios
- previous attempts
- recovery actions
- recovery outcomes
- historical recovery cases

These fields are explicitly synthetic and are not claimed to represent Razorpay internal data.

---

# 2. Common Revenue-at-Risk Event

All three revenue surfaces share these core fields.

| Field | Type | Origin | Description |
|---|---|---|---|
| event_id | string | Derived | Unique identifier for the Vaidya event |
| event_type | string | Synthetic/Derived | payment_failure, checkout_abandonment, or overdue_invoice |
| timestamp | datetime | Public/Derived | Time associated with the event |
| customer_id | string | Derived | Anonymous customer identifier |
| amount_at_risk | float | Derived/Synthetic | Revenue currently at risk |
| currency | string | Synthetic | Currency used by the demo, INR |
| fraud_flag | boolean | Public/Derived | Whether the event has a fraud/risk signal |

### Important

`amount_at_risk` represents money that has not successfully been collected.

It is NOT automatically equal to money that will eventually be recovered.

# 3. Payment Failure Event

## Purpose

Represents a payment attempt where expected revenue was not successfully collected.

### Schema

| Field | Type | Origin | Description |
|---|---|---|---|
| event_id | string | Derived | Unique Vaidya event ID |
| event_type | string | Synthetic | Always `payment_failure` |
| timestamp | datetime | Public/Derived | Payment event timestamp |
| customer_id | string | Derived | Anonymous customer identifier |
| amount_at_risk | float | Public/Derived | Failed payment amount |
| currency | string | Synthetic | INR |
| merchant | string | Public Dataset | Merchant associated with transaction |
| merchant_category | string | Public Dataset | Transaction category |
| payment_method | string | Synthetic | Card, UPI, wallet, netbanking, etc. |
| payment_status | string | Synthetic | Failed/pending/etc. |
| error_code | string | Synthetic | Structured failure code |
| error_description | string | Synthetic | Human-readable failure description |
| error_source | string | Synthetic | Bank, gateway, customer, etc. |
| error_step | string | Synthetic | Stage where failure occurred |
| error_reason | string | Synthetic | Root failure scenario |
| fraud_flag | boolean | Public Dataset | Fraud signal |
| previous_attempts | integer | Synthetic | Number of previous payment attempts |

### Example

```text
event_id: PAY_001
event_type: payment_failure
timestamp: 2026-08-29 10:30:00
customer_id: CUST_1042

amount_at_risk: 24500
currency: INR

merchant: UrbanCart
merchant_category: grocery

payment_method: UPI
payment_status: failed

error_code: BANK_TIMEOUT
error_description: Bank did not respond within the allowed window
error_source: bank
error_step: authorization
error_reason: temporary_bank_timeout

fraud_flag: false
previous_attempts: 1
